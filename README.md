Сравнение пяти самостоятельно реализованных моделей персональных top-10 рекомендаций новых товаров:
ItemKNN, iALS, EASE, FM с метаданными и iALS с собственным таргетом давности и частоты покупок.
Готовые рекомендательные реализации и scikit-learn не используются.

Основной отчёт — [experiments.ipynb](experiments.ipynb): выполненные ячейки, EDA, формулы,
подбор на validation, общая таблица test, графики и выводы. В `results/` сохранены агрегированные результаты.

## Данные и постановка

Из 541 909 исходных строк после удаления покупок без user ID, отмен, неположительных цены/количества,
служебных SKU и точных дубликатов остаются **391 150 событий, 4 334 пользователя и 3 659 товаров**.
Уникальных user-item пар — **266 221**; случайной подвыборки нет. Число различных счетов отражает частоту,
количество единиц не используется как сила интереса из-за оптовых покупателей.

Задача: для известного пользователя рекомендовать 10 ещё не купленных товаров из всего известного каталога.
Релевантность — успешная покупка нового товара в будущем окне, одинаковая для всех моделей.
Train — до 01.09.2011; validation — 01.09–14.10.2011; test — с 15.10.2011 до конца файла.
Основная метрика, выбранная до подбора, — **NDCG@10**; дополнительно Recall@10, Precision@10 и Coverage@10.
После подбора выполняется refit на train + validation. На всех моделях совпадают пользователи,
полный каталог кандидатов и исключение известных товаров. Условия warm-start и число исключений раскрыты в ноутбуке.

FM использует ID, историческую страну пользователя, токены последнего известного названия товара
и дециль исторической медианы цены. Кодирование полностью строится на соответствующей обучающей истории.
Есть контрольная абляция FM только с ID.

Собственный таргет: `p_RF = (1 - exp(-n_invoices/2)) * 2**(-age_days/half_life)` для наблюдаемых пар,
ноль для остальных. Confidence и структурные параметры те же, что у выбранного базового iALS;
меняется целевое `p`, а не только вес ошибки. Формулы и парное сравнение приведены в ноутбуке.

## Результаты

Test: **1 587 пользователей**, полный каталог из **3 556 товаров** перед исключением истории каждого пользователя.

| Модель | NDCG@10 | Recall@10 | Precision@10 | Coverage@10 |
|---|---:|---:|---:|---:|
| EASE | 0.1026 | 0.0583 | 0.0877 | 0.2396 |
| ItemKNN | 0.0966 | 0.0550 | 0.0812 | 0.2629 |
| iALS | 0.0939 | 0.0538 | 0.0794 | 0.2821 |
| RF-iALS | 0.0849 | 0.0494 | 0.0715 | 0.2182 |
| FM с метаданными | 0.0752 | 0.0418 | 0.0672 | 0.1957 |

Лучший EASE использует `reg=1000`, выбранную на validation. Собственный сигнал снизил NDCG относительно базового iALS
на 0.0090 (95% парный bootstrap CI: −0.0147…−0.0035). Разница FM с метаданными и FM только с ID — −0.0019,
её CI включает ноль (−0.0070…+0.0032); убедительного улучшения от метаданных в этом запуске нет.
Все параметры, результаты поиска и численные выводы доступны в ноутбуке и `results/`.

## Воспроизведение

Python **3.12**, CPU, ориентировочно 2–4 GB свободной RAM. Из корня репозитория:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/run_notebook.py
```

На Windows активация: `.venv\Scripts\activate`.
Данные скачиваются автоматически с UCI (22.6 MB) при первом запуске. SHA256 исходного архива:
`f5385cbb54bbebf7196389109c6b0621faab0c304e3702548165e71c84aede8b`.
Файл с другой контрольной суммой не используется. Можно также открыть ноутбук в Jupyter/VS Code,
выбрать интерпретатор `.venv` и выполнить Run All. Отдельная установка ядра не нужна для скрипта запуска.

Зафиксированы seed=42, один вычислительный поток, версии основных библиотек, правила очистки,
пространства поиска и календарные границы. Параметры не корректируются по test.
На другой платформе/BLAS допустимы небольшие численные отклонения.
Полный запуск перезаписывает ноутбук и результаты. Продолжительность зависит от CPU.

## Структура

```text
experiments.ipynb        Выполненный основной отчёт
models/item_knn.py      Item-based cosine CF со shrinkage
models/ials.py          iALS: собственные нормальные уравнения ALS
models/ease.py          EASE: замкнутое решение
models/fm.py            FM: собственная формула и negative sampling, PyTorch autograd
models/custom_ials.py   iALS с таргетом давности и частоты
models/base.py          Общая маска истории и детерминированный top-K
data_utils.py           Загрузка, очистка, временной протокол и признаки
evaluation.py           Метрики и парный bootstrap
tests/                  Математические проверки реализаций
scripts/run_notebook.py Полное выполнение в текущем Python
scripts/build_notebook.py Генератор исходной структуры отчёта
results/                Агрегированные таблицы, параметры, аудит и выводы
figures/                Графики из ноутбука
requirements.txt        Зависимости
.gitignore              Исключения для данных, окружения, весов и кешей
```

`scripts/build_notebook.py` предназначен для редактирования структуры отчёта: он очищает outputs,
поэтому после него нужно заново выполнить `scripts/run_notebook.py`. Для обычного повторения достаточно второго скрипта.
Исходные покупки, виртуальное окружение и веса моделей в репозиторий не включаются.

## Методические ограничения

Один магазин и временной период, оптовики и доминирование Великобритании ограничивают переносимость.
Протокол оценивает активных известных пользователей с новыми релевантными покупками; повторы и cold-start исключены.
Доступность товаров на складе и показы неизвестны. Небольшой поиск при одном seed не доказывает превосходство
модели при любом бюджете. Подробные выводы по фактическим результатам — в ноутбуке и `results/conclusions.md`.
